[01]适用场景与硬性要求 When and the hard rule

先确认你真的需要走这条路Make sure this is the right route for you

ShadowMountPlus 官方把 exFAT 定位为「只给那些不按外置盘方式处理就跑不正常的游戏」。如果你的游戏在文件夹格式下一切正常，官方推荐的是 UFS2（.ffpkg）——步骤更少、不产生 macOS 残留、空间效率也更高。

那什么时候该选 exFAT：

  • 某个游戏用文件夹格式或 .ffpkg 跑起来卡顿、音画异常、读不到数据，改成「外置盘内容」后就正常了。
  • 你不想安装任何第三方工具，只想用 macOS 自带命令解决。
  • 你需要能手工修改镜像内容（exFAT 镜像可以挂载后用 Finder 直接改）。
Choose exFAT when a specific title only works as external-drive content, when you want zero third-party tools, or when you need to edit the image contents by hand afterwards.
[!] 唯一一条不能商量的硬性要求：簇大小必须是 64 KiB

ShadowMountPlus 官方 README 原话：

"If you create an exFAT (.exfat) image manually, use a 64 KB cluster size. Smaller clusters can cause a noticeable performance loss."

本页所有命令都围绕这一点。用错簇大小，游戏能挂上但会明显掉性能。而且 newfs_exfat 的默认值不保证是 64 KiB，必须显式指定。

[02]前置检查 Pre-flight

exFAT 专属的三项确认Three checks specific to this route

2.1确认系统命令齐全 Check the built-in tools

这套流程全部使用 macOS 自带命令，从 10.6.5 起就有，不需要装任何东西，也不需要 sudo。

bash六个命令都要有输出

>   printf "%-12s %s\n" "$c" "$(command -v $c || echo MISSING)"
> done

diskutil     /usr/sbin/diskutil
rsync        /usr/bin/rsync
dot_clean    /usr/sbin/dot_clean
shasum       /usr/bin/shasum

newfs_exfat 是 macOS 自带的 exFAT 格式化工具。Linux 上对应的叫 mkfs.exfat，别搞混。

On Linux the equivalent formatter is mkfs.exfat; on macOS it is newfs_exfat. Everything here ships with macOS.

2.2算一下镜像要多大 Size the image

exFAT 的每个文件都会按 64 KiB 簇向上取整，零碎文件多的游戏会明显变大。用这个计算器按官方算法估一下：

镜像大小计算器 / image size calculator

Formula from the official ShadowMountPlus macOS script: per-file cluster rounding + FAT + allocation bitmap + directory entries + 32 MiB fixed metadata + 0.5% spare (clamped to 64–512 MiB).

[X] 别忘了两倍空间

如果源目录和镜像在同一块盘上（最常见），你需要大约两倍的可用空间——游戏和镜像会同时存在。

2.3确认源目录结构 Check the source layout

游戏文件必须直接在目录根下，不能多套一层。ShadowMountPlus 靠根目录的 eboot.bin 与 sce_sys/param.json 识别游戏（详见总览 4.1）。

bash两个文件都必须存在
$ GAME="/Volumes/MYSSD/downloads/ps5/PPSA12345"
$ ls "$GAME/eboot.bin" "$GAME/sce_sys/param.json"

3.3中途断了怎么办 Resuming

233 GB 拷到一半断电、或者手滑关了终端——别重来。REUSE=1 会复用已经格式化好的镜像，只补没拷完的部分：

bash断点续传
$ REUSE=1 ~/bin/smp-mkexfat.sh \
>   "/Volumes/MYSSD/downloads/ps5/PPSA12345" \
>   "/Volumes/MYSSD/homebrew/PPSA12345.exfat"
复用已格式化的镜像 / reusing formatted image: 148G
[!] 不加 REUSE=1 会重新开始

默认行为是删除并重建镜像文件。续传时一定要带 REUSE=1，否则前面拷贝的 148 GB 会被丢掉。

脚本相对官方 mkexfat_macos.sh 的三处改进：强制 64 KiB 簇、自动剔除 .DS_Store/._*/发布组垃圾、复制后自动比对文件数与总字节数。

[04]手敲命令 · 八步 Manual, eight steps

每一步都可单独执行和检查Each step can be run and inspected on its own
[i] 变量会一路沿用

按顺序执行时，GAME、D、MNT 赋值一次后续直接复用。要单独跑某一步，把上一步的变量定义一起复制过去，否则会拿到空值。想完全省心就用第 07 节的整段脚本。

4.1量一下体积 Measure the source

bash记下这个数字，下一步要用
$ GAME="/Volumes/MYSSD/downloads/ps5/PPSA12345"
$ du -sh "$GAME"
233G	/Volumes/MYSSD/downloads/ps5/PPSA12345

按「游戏体积 + 1～2 GB」来定镜像大小。233 GB 的游戏，做 235 GB 的镜像就够。

Size the image at roughly the game size plus 1–2 GB.

4.2建空白稀疏镜像 Create a blank sparse image

bash瞬间完成，不会真的写 235 GB 的零
$ cd /Volumes/MYSSD/homebrew
$ mkfile -n 235g PPSA12345.exfat
$ ls -lh PPSA12345.exfat
-rw-------  1 user  staff   235G  PPSA12345.exfat

-n 表示「不要真正写入数据」，只建一个稀疏文件，所以 235 GB 的镜像会瞬间创建好，实际占用由后续写入量决定。

mkfile -n is the macOS equivalent of Linux's truncate -s: it allocates instantly without writing zeros.

4.3把镜像挂成设备 Attach as a block device

bash拿到 /dev/diskN 设备节点
$ D=$(diskutil image attach --noMount PPSA12345.exfat | awk '{print $1}')
$ echo "$D"
/dev/disk6
[X] 为什么不能直接格式化镜像文件？

因为 newfs_exfat 需要一个带真实扇区几何信息的块设备。直接喂给它一个普通文件会报 newfs_exfat: /dev/xxx.exfat: No such file or directory——它把你的文件名当成 /dev 下的设备去找了。

On macOS 26 and later hdiutil attach -nomount is deprecated; diskutil image attach --noMount is the modern replacement.

4.4格式化成 64 KiB 簇的 exFAT Format with 64 KiB clusters

bash最关键的一步
$ newfs_exfat -b 65536 -v PPSA12345 "/dev/r${D##*/}"
Volume name      : PPSA12345
Volume size      : 489674752 sectors (250713473024 bytes)
Bytes per sector : 512
Bytes per cluster: 65536
FAT offset       : 2048 sectors (1048576 bytes)
# FAT sectors    : 30720
Number of FATs   : 1
Cluster offset   : 32768 sectors (16777216 bytes)
# Clusters       : 3825328
  • -b 65536：注意 -b 直接传「字节/簇」，不是扇区数。65536 字节正好是官方要求的 64 KiB。
  • -v：卷标，设成标题 ID 方便识别。
  • /dev/rdiskN 里的 r 表示 raw 裸设备，比带缓冲的设备快。

输出里的 Bytes per cluster: 65536 就是成功标志。这一步错了，后面全白做。

The -b flag takes bytes per cluster, not sectors. 65536 bytes = 64 KiB, exactly what ShadowMountPlus requires.

4.5挂载它 Mount it

bash必须用 diskutil mount
$ diskutil mount "$D"
$ MNT="/Volumes/PPSA12345"
$ mount | grep "^$D "
Volume PPSA12345 on /dev/disk6 mounted
[X] 不要用 mount -t exfat

很多老教程写的是 sudo mount -t exfat …。但在较新的 macOS 上这会失败：

mount_exfat: exfat filesystem is not available
mount: … failed with 71

一律改用 diskutil mount，它会正确处理驱动加载，而且不需要 sudo。

4.6拷贝游戏文件 Copy the files

bashrsync 参数保持最简，这点很重要
$ rsync -r --progress \
>   --exclude='.DS_Store' --exclude='._*' \
>   --exclude='_DUPLEX_'  --exclude='GKinto.com.txt' \
>   "$GAME"/ "$MNT"/
eboot.bin
        259129280 100%  182.53MB/s   00:01:21 (xfer#14, to-check=91/105)
prx/
prx/akgain.prx
         1234567 100%  140.11MB/s   00:00:00 (xfer#15, to-check=89/105)
[X] 别给 rsync 加 -ltDHh 之类的参数

这是本页最反直觉的一条。macOS 源文件带有一个删不掉的 com.apple.provenance 扩展属性，一旦 rsync 试图传递时间戳/硬链接/设备号，macOS 就会为每个文件额外塞一个 ._文件名 的影子文件进镜像。

实测：-ltDHh 会生成一堆 ._eboot.bin、._sce_sys；而官方的 rsync -r --progress 一个都不会生成。参数越少越干净。

Counter-intuitive but important: keep rsync's flags minimal. Extra flags such as -ltDHh make macOS emit AppleDouble ._* companion files for every source file.

4.7清理 macOS 残留 Clean leftovers

bash顺序有讲究，别调换
$ dot_clean -m "$MNT"
$ rm -rf "$MNT/.fseventsd" "$MNT/.Spotlight-V100"
$ rm -rf "$MNT/.Trashes"          # 必须最后删
$ find "$MNT" -name '._*' -delete
$ ls -a "$MNT"                    # 确认只剩游戏文件
  • dot_clean -m：把万一产生的 ._* 影子文件合并/清掉，macOS 自带的官方工具。
  • 删除顺序必须是「先 .fseventsd，最后 .Trashes」。反过来的话，删 .fseventsd 会被丢进废纸篓，反而把 .Trashes 又重建出来。

4.8落盘并卸载 Flush and unmount

bashsync 别省，200 GB 写缓存不能靠运气
$ sync
$ diskutil unmount "$MNT"
$ diskutil eject "$D"
Volume PPSA12345 on disk6 unmounted
"disk6" ejected.

macOS aggressively caches writes in RAM. Always sync and let the unmount finish before unplugging anything — skipping this on a 200 GB image is how you get a corrupt image.

[05]校验镜像 Verify

四项独立检查，不依赖任何工具的自述Four independent checks that don't trust the builder

5.1直接读引导扇区，验簇大小 Read the boot sector

不挂载文件系统，直接从镜像的 exFAT 引导扇区（BPB）里读参数。这是最硬的证据：

bash偏移 108 = 扇区位移，109 = 每簇扇区位移
$ IMG=/Volumes/MYSSD/homebrew/PPSA12345.exfat
$ od -An -tu1 -j 108 -N 2 "$IMG" | awk 'NR==1{printf "扇区 %d B × 每簇 %d 扇区 = 每簇 %d B\n", 2^$1, 2^$2, 2^$1*2^$2}'
$ dd if="$IMG" bs=1 skip=3 count=5 2>/dev/null; echo
$ od -An -tu8 -j 72 -N 8 "$IMG" | awk 'NR==1{printf "%d 扇区 × 512 = %.2f GiB\n", $1, $1*512/1024/1024/1024}'
扇区 512 B × 每簇 128 扇区 = 每簇 65536 B
EXFAT
489674752 扇区 × 512 = 233.50 GiB

512 × 128 = 65536，说明簇大小正是 64 KiB。EXFAT 说明文件系统标识正确。

[!] macOS 的 od 会多输出一个空行

所以上面两条 od 命令都加了 awk 'NR==1{...}' 只取第一行。不加守卫的话，od 尾部的空行会被 awk 当成一行数据，多打印出 扇区 1 B × 每簇 1 扇区 = 每簇 1 B 这样一行错误结果。

不想依赖 od，也可以直接读这两个原始字节：xxd -s 108 -l 2 -p "$IMG" 输出 0907，即 0x09 = 9、0x07 = 7，同样得出 2^9 × 2^7 = 65536。

Offset 108 holds the bytes-per-sector shift, offset 109 the sectors-per-cluster shift. 2^9 × 2^7 = 65536.

5.2挂载后核对文件数与总字节 Compare counts and bytes

bash源与镜像必须完全一致
$ IMG=/Volumes/MYSSD/homebrew/PPSA12345.exfat
$ D=$(diskutil image attach --noMount "$IMG" | awk '{print $1}')
$ diskutil mount "$D" >/dev/null; MNT="/Volumes/PPSA12345"
$ echo "文件数: $(find "$MNT" -type f | wc -l | tr -d ' ')"
$ find "$MNT" -type f -print0 | xargs -0 stat -f '%z' | awk '{s+=$1} END {print "总字节:", s}'
文件数: 105
总字节: 250122409030
[i] 小技巧：为什么用 xargs 而不是 find -exec

find … -exec stat -f '%z' {} \; 在某些受限环境里会因为引号处理方式不同而报 stat: '%z': No such file or directory。改成 -print0 | xargs -0 stat 更稳也更快。

5.3抽查大文件的哈希 Spot-check a hash

bash两行哈希必须一模一样
$ MNT="/Volumes/PPSA12345"
$ GAME="/Volumes/MYSSD/downloads/ps5/PPSA12345"
$ shasum -a 256 "$MNT/eboot.bin" "$GAME/eboot.bin"
4f2a9c1e7b3d05a8c6e1f9042b7d8e3a5c0f6b2194d8e7a3c5b1f0d6928e4a7c  /Volumes/PPSA12345/eboot.bin
4f2a9c1e7b3d05a8c6e1f9042b7d8e3a5c0f6b2194d8e7a3c5b1f0d6928e4a7c  /Volumes/MYSSD/downloads/ps5/PPSA12345/eboot.bin

A matching SHA-256 on a large file is the strongest practical proof that the copy is intact.

5.4确认根目录没有垃圾 Check for junk

bash除了 .fseventsd，其余都该为空
$ MNT="/Volumes/PPSA12345"
$ ls -a "$MNT"
$ find "$MNT" \( -name '._*' -o -name '.DS_Store' -o -name '.Trashes' \) | wc -l
.  ..  .fseventsd  ampr_emu.index  eboot.bin  engine  fakelib
live  package.manifest  prx  sce_module  sce_sys
0
[!] .fseventsd 是正常的，删不掉也不用删

只要你在 macOS 上挂载过这个 exFAT 卷，系统就会自动生成一个空的 .fseventsd 目录。这是 macOS 的文件事件日志机制，每次挂载都会重建，无法根除（官方脚本干脆不处理）。它只是个空目录，对 PS5 侧完全无影响。

最后卸载：

bash先取回设备节点，再卸载
$ MNT="/Volumes/PPSA12345"
$ D=$(mount | grep " on $MNT " | awk '{print $1}')
$ diskutil unmount "$MNT" && diskutil eject "$D"

[07]命令速查 Cheat sheet

自包含，可整段复制后改路径直接跑Self-contained — copy, change paths, run
bash八步全流程
# 变量：源目录 / 镜像文件 / 卷标
GAME="/Volumes/MYSSD/downloads/ps5/PPSA12345"
IMG="/Volumes/MYSSD/homebrew/PPSA12345.exfat"
LABEL="PPSA12345"

# 1) 建稀疏镜像（大小 = 游戏体积 + 1~2GB）
mkfile -n 235g "$IMG"

# 2) 挂成块设备
D=$(diskutil image attach --noMount "$IMG" | awk '{print $1}')

# 3) 格式化为 64 KiB 簇 exFAT
newfs_exfat -b 65536 -v "$LABEL" "/dev/r${D##*/}"

# 4) 挂载
diskutil mount "$D"
MNT="/Volumes/$LABEL"

# 5) 拷贝（参数保持最简）
rsync -r --progress \
  --exclude='.DS_Store' --exclude='._*' \
  --exclude='_DUPLEX_' --exclude='GKinto.com.txt' \
  "$GAME"/ "$MNT"/

# 6) 清理 macOS 残留
dot_clean -m "$MNT"
rm -rf "$MNT/.fseventsd" "$MNT/.Spotlight-V100"
rm -rf "$MNT/.Trashes"
find "$MNT" -name '._*' -delete

# 7) 校验（应输出 512 x 128 = 65536 bytes/cluster）
od -An -tu1 -j 108 -N 2 "$IMG" | awk 'NR==1{printf "%d x %d = %d bytes/cluster\n", 2^$1, 2^$2, 2^$1*2^$2}'
find "$MNT" -type f | wc -l

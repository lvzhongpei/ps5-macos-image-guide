UFS2 镜像 · .ffpkg

[01]为什么这是首选 Why this is the default

它解决的是 exFAT 路线上那些别扭的地方It removes the awkward parts of the exFAT route

ShadowMountPlus 的 README 把 .ffpkg（UFS2）列为常规场景的推荐格式，把 .exfat 降级为「给需要外置盘式兼容的游戏用」。原因很实在：

.ffpkg.exfat
建镜像的方式直接按字节构造文件系统挂载后由 macOS 写入
需要挂载吗不需要需要
macOS 残留文件完全不会产生会带出 ._* / .fseventsd
命令数量一条八步
能自检文件系统吗能，fsck_ufs只能比对文件数与字节数
空间开销更小64 KiB 簇末填充浪费更多
放内置 SSD直接可用需要额外的只读 / 扇区设置
[!] 那什么时候还是得用 exFAT

只有一种：某个游戏只有在被当成「外置盘内容」处理时才正常——例如文件夹格式或 .ffpkg 下卡顿、音画异常、读不到数据。这种情况请改看 exFAT 教程。

1.1为什么它不需要挂载 Why no mounting is needed

因为 macOS 根本不能原生挂载 UFS2——这本来是个限制，反而成了优势。既然没法挂载，工具就只能自己动手：UFS2Tool 直接按字节写出 superblock、柱面组、inode 表和数据块。整个过程中 macOS 的文件系统驱动完全没有参与，自然也就不会塞进 ._* 影子文件或 .fseventsd 目录。

macOS cannot mount UFS2 natively. That constraint is exactly why the route is clean: UFS2Tool writes the filesystem structure itself, byte by byte, so the macOS filesystem driver never touches the image.

[02]安装 UFS2Tool Install UFS2Tool

下载、校验、去隔离，三步Download, verify, de-quarantine

工具是 SvenGDK/UFS2Tool（BSD-2-Clause 开源，跨平台）。它基于 .NET 8，但官方提供了自带运行时的自包含版本，所以你不需要安装 dotnet。

2.1选对包 Pick the right archive

你的机器下载这个大小
Apple Silicon（M1–M4）osx-arm64-selfcontained.zip约 40 MB
Intel Macosx-x64-selfcontained.zip约 41.5 MB

先确认自己的架构，然后下载。本页以 v4.1 为例：

bash确认架构 + 下载
$ uname -m
$ mkdir -p ~/UFS2Tool && cd ~/UFS2Tool
$ curl -fL -o ufs2.zip \
>   https://github.com/SvenGDK/UFS2Tool/releases/download/v4.1/osx-arm64-selfcontained.zip
arm64

The self-contained builds bundle the .NET 8 runtime, so you do not need to install dotnet separately. Intel Macs use the osx-x64-selfcontained.zip asset instead.

2.2校验校验和 Verify the checksum

下载完先比对官方 release 页面上的 sha256。别跳过这一步——这是一个会写文件系统结构的工具，来源必须可信。

bash期望输出 OK
$ echo "3b2eb0044e62210f88a44432f0d64301a1f810d6ef7720f68281f565651ef10b  ufs2.zip" | shasum -a 256 -c -
ufs2.zip: OK
[i] 这里的哈希是 osx-arm64-selfcontained.zip v4.1 的

Intel 版是 d354d8444e6da8fb682a6fb5d7067dd9d5750b8a8088cddac51a3eefec25f778。换了版本号，哈希也会变——以 release 页面当时公布的为准。

2.3解压、去隔离、赋权 Extract, de-quarantine, chmod

bashxattr 这一步不能省
$ unzip -q ufs2.zip
$ cd osx-arm64-selfcontained
$ chmod +x UFS2Tool UFS2Tool.GUI
$ xattr -r -d com.apple.quarantine .
$ ./UFS2Tool
[X] 不去 quarantine 会被 Gatekeeper 拦下

从网上下载的二进制会被 macOS 打上隔离标记，直接运行会提示「无法打开，因为 Apple 无法检查其是否包含恶意软件」或者静默拒绝执行。xattr -r -d com.apple.quarantine . 必须跑。

跑通的话会打印出完整的命令列表，其中最关键的一条是：

output从 -D 的说明里能看出它的用途output only
  newfs   -D <input-directory> <image-path> [volume-name]
          Create image from directory contents (size auto-calculated)

There is also a GUI (./UFS2Tool.GUI, Avalonia-based) with a dedicated PS5 tab that supports batch conversion of multiple folders. The CLI is what this guide uses.

[04]手敲命令与参数 Manual, with the parameters explained

其实只有一条命令，但参数值得看懂Really just one command — but the flags are worth understanding

4.1官方最简写法 The official quick start

UFS2Tool 的 README 里给了 PS5 的快速上手命令，尺寸会自动计算：

bash会自动算大小，并用默认参数建 UFS2
$ GAME="/Volumes/MYSSD/downloads/ps5/PPSA12345"
$ ./UFS2Tool newfs -D "$GAME" "/Volumes/MYSSD/homebrew/PPSA12345.ffpkg"
Image created successfully.

UFS2 Filesystem Image: PPSA12345.ffpkg
Magic: 0x19540119 (Valid UFS2)
Block Size: 32768 bytes
Fragment Size: 4096 bytes
Total Size: 15 MB

-D 后面跟源目录，第二个位置参数是输出路径，可以直接写成 .ffpkg 后缀，不需要先建 .img 再改名。

4.2显式指定 PS5 常用参数 Pin the parameters explicitly

社区工具（如 PSFFPKG）在调 UFS2Tool 时会显式指定这几个参数。想完全可控就用这条：

bashUFS2 + 32 KiB block + 4 KiB fragment
$ ./UFS2Tool newfs -O 2 -b 32768 -f 4096 -D "$GAME" "/Volumes/MYSSD/homebrew/PPSA12345.ffpkg"
参数含义为什么是这个值
-O 2文件系统版本，2 = UFS2PS5 原生用的就是 UFS2
-b 32768block 大小 32 KiB社区工具验证过的 PS5 常用值（范围 4096–65536）
-f 4096fragment 大小 4 KiB碎片级分配，小文件浪费最少
-D <目录>从目录内容填充，自动算尺寸免去手工估算 -s
-S 4096扇区大小官方 makefs 写法里用；UFS2Tool v4.1 起已把布局统一规范化到 512，一般不必手动指定
-m 0保留空间百分比官方 makefs 写法用 0，避免为「给 root 预留」白白占空间
[i] 官方还给了 makefs 的等价写法

如果你更喜欢 FreeBSD makefs(8) 风格的参数，README 里也有：

UFS2Tool makefs -S 4096 -t ffs -o version=2,minfree=0,softupdates=0,optimization=space <输出>.ffpkg <源目录>

注意 makefs 的参数顺序是先输出后输入，跟 newfs -D 相反。

4.3先干跑一遍看参数 Dry run first

加 -N 只打印参数、不真正建文件。大游戏开工前建议先跑一次，确认自动算出的尺寸合理：

bash-N = dry run
$ ./UFS2Tool newfs -N -O 2 -b 32768 -f 4096 -D "$GAME" test.ffpkg
  Input directory: /Volumes/MYSSD/downloads/ps5/PPSA12345
  Directory size:  4,900,099 bytes (4.67 MB)
  Auto-sized to:   16,220,160 bytes (15 MB)

  Format:        UFS2 (-O 2)
  Block size:    32768 bytes (-b)
  Fragment size: 4096 bytes (-f)
  Sector size:   512 bytes (-S)
  Total size:    16,220,160 bytes (15 MB)
  Cylinder groups: 1
  Min free:      8% (-m)
  Optimization:  time (-o)

Dry run (-N): filesystem was NOT created.

Unlike the exFAT route, there is no sparse-file sizing step and no "2× disk space" requirement for the source and image living side by side — but you still need room for the image itself.

4.4别忘了源目录结构 Mind the source layout

游戏文件必须在源目录根下，eboot.bin 与 sce_sys/param.json 缺一不可（详见总览 4.1）。UFS2Tool 会校验 eboot.bin 是否存在，但不认目录层级——多套一层它会照样打包，结果 PS5 认不出来。

[05]校验镜像 Verify

UFS2Tool 自己就是检查工具，四项独立验证The same tool verifies it — four independent checks

5.1读文件系统信息 Read the filesystem info

bashMagic 必须是 0x19540119
$ IMG=/Volumes/MYSSD/homebrew/PPSA12345.ffpkg
$ ./UFS2Tool info "$IMG"
UFS2 Filesystem Image: PPSA12345.ffpkg
Magic: 0x19540119 (Valid UFS2)
Block Size: 32768 bytes
Fragment Size: 4096 bytes
Cylinder Groups: 1
Inodes Per Group: 2048
Total Fragments: 3960
Total Size: 15 MB
Directories: 3

Magic: 0x19540119 (Valid UFS2) 是 UFS2 的超级块魔数，这一行出现就说明文件系统结构本身是合法的。

0x19540119 is the UFS2 superblock magic. Seeing it means the filesystem structure is valid, not just that a file was written.

5.2列出目录树 List the tree

bash先看根，再看子目录
$ ./UFS2Tool ls "$IMG"
$ ./UFS2Tool ls "$IMG" sce_sys

  DIR   inode=     2  ..

5.3跑一遍文件系统一致性检查 Run fsck

这是 exFAT 路线给不了的东西：真正的文件系统级自检。

bash-f 强制检查、-n 只读不修
$ ./UFS2Tool fsck_ufs -fn "$IMG"
** Checking UFS2 filesystem image: PPSA12345.ffpkg
** Phase 1 - Check Blocks and Sizes
** Phase 2 - Check Pathnames
** Phase 3 - Check Connectivity
** Phase 4 - Check Reference Counts
** Phase 5 - Check Cylinder Groups
** PPSA12345.ffpkg is clean
8 files, 1251 used, 2540 free (1.1% fragmentation)

看到 is clean 就说明超级块、inode 链、块位图、目录引用计数全都没问题。

5.4抽出关键文件比对哈希 Extract and hash

最后做一次数据层面的抽验：把 eboot.bin 单独抽出来，和源文件比 SHA-256。不用全量解包，所以即使是 200 GB 的游戏也只花几秒。

bash两行哈希必须一模一样
$ GAME="/Volumes/MYSSD/downloads/ps5/PPSA12345"
$ ./UFS2Tool extract "$IMG" /tmp/ufscheck eboot.bin
$ shasum -a 256 "$GAME/eboot.bin" /tmp/ufscheck/eboot.bin
4f2a9c1e7b3d05a8c6e1f9042b7d8e3a5c0f6b2194d8e7a3c5b1f0d6928e4a7c  /Volumes/MYSSD/downloads/ps5/PPSA12345/eboot.bin
4f2a9c1e7b3d05a8c6e1f9042b7d8e3a5c0f6b2194d8e7a3c5b1f0d6928e4a7c  /tmp/ufscheck/eboot.bin

Spot-checking one large file avoids unpacking hundreds of gigabytes while still proving the data path is intact.

[06]专属排错 Troubleshooting

这条路线的坑都集中在工具链上The pitfalls on this route are all about the toolchain
现象原因处理
提示「无法打开，因为 Apple 无法检查其是否包含恶意软件」 下载的二进制带 quarantine 隔离标记 xattr -r -d com.apple.quarantine .
Permission denied 无法执行 解压后没有执行权限 chmod +x UFS2Tool UFS2Tool.GUI
报找不到 .NET 运行时 下载成了非 self-contained 的那个包 换 osx-arm64-selfcontained.zip（自带运行时），不用装 dotnet
bad CPU type in executable 架构选错了（Apple Silicon 装了 x64 包，或反之） uname -m 确认后换对应包
镜像建好了但 PS5 识别不到 源目录多套了一层，或镜像没放在 homebrew/ 第一层 用 UFS2Tool ls 确认根下有 eboot.bin；检查盘内位置
镜像比预期大很多 自动尺寸留了余量（元数据 + 安全边际） 正常。想精确控制就自己算好，用 newfs [options] <镜像> <大小MB> 代替 -D
游戏卡顿 / 音画异常 该游戏需要「外置盘式」处理 改做 .exfat，见 exFAT 教程
APR-Emu 游戏在内置 SSD 启动失败 缺 ampr_emu.index 或只读设置不对 确认镜像根下有该索引文件，并检查 ShadowMountPlus 的只读 / 扇区设置
想直接挂载镜像看内容 macOS 不支持原生挂载 UFS2 用 UFS2Tool ls / extract；GUI 版还有内容浏览器
[X] 重要：不要用 ShadowMountPlus 仓库里的 mkufs2.sh

ShadowMountPlus 仓库根目录有一个 mkufs2.sh，看起来很像是官方给的 UFS2 构建脚本。但它是 FreeBSD 专用的——里面用的是 mdconfig、newfs -O 2、mount，macOS 上根本没有这些命令（它里面的 stat -f 是 BSD 语法，容易让人误以为跨平台）。

在 macOS 上做 UFS2 镜像，请一律使用 UFS2Tool。

如果问题不在工具链上（例如 PS5 识别不到、挂载后没反应），看总览的公共排错表。

[07]命令速查 Cheat sheet

自包含，可整段复制后改路径直接跑Self-contained — copy, change paths, run
bash从下载工具到构建 + 自检
# 变量
GAME="/Volumes/MYSSD/downloads/ps5/PPSA12345"
IMG="/Volumes/MYSSD/homebrew/PPSA12345.ffpkg"
TOOL="$HOME/UFS2Tool/osx-arm64-selfcontained/UFS2Tool"

# 1) 准备工具（只需做一次）
mkdir -p "$HOME/UFS2Tool" && cd "$HOME/UFS2Tool"
curl -fL -o ufs2.zip \
  https://github.com/SvenGDK/UFS2Tool/releases/download/v4.1/osx-arm64-selfcontained.zip
echo "3b2eb0044e62210f88a44432f0d64301a1f810d6ef7720f68281f565651ef10b  ufs2.zip" | shasum -a 256 -c -
unzip -q ufs2.zip
cd osx-arm64-selfcontained
chmod +x UFS2Tool UFS2Tool.GUI
xattr -r -d com.apple.quarantine .

# 2) 干跑确认参数与尺寸
"$TOOL" newfs -N -O 2 -b 32768 -f 4096 -D "$GAME" "$IMG"

# 3) 正式构建（一条命令）
"$TOOL" newfs -O 2 -b 32768 -f 4096 -D "$GAME" "$IMG"

# 4) 校验：魔数
"$TOOL" info "$IMG"
# 5) 校验：目录树
"$TOOL" ls "$IMG"
# 6) 校验：文件系统一致性（期望 is clean）
"$TOOL" fsck_ufs -fn "$IMG"
# 7) 校验：抽一个文件比哈希
"$TOOL" extract "$IMG" /tmp/ufscheck eboot.bin
shasum -a 256 "$GAME/eboot.bin" /tmp/ufscheck/eboot.bin
[OK] 做完了

把它放进 <盘根>/homebrew/ 或 /data/homebrew/ 即可，详见总览第 05 节。
